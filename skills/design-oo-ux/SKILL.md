# Design OO UX

## When to Use This Skill
- Class/method design, encapsulation, inheritance vs composition.
- Which UML diagram to draw (static vs dynamic vs functional).
- Prototype fidelity choice (paper/wireframe vs mockup vs high-fidelity) and POUR accessibility.

## Route elsewhere
- Visual feel/execution -> superpowers apple-design (vendored in fork; authoritative for gestures, springs, materials, typography, eight principles). This skill submits to it and only adds structural input; on conflict apple-design wins.
- Visual execution at scale -> external ui-ux-pro-max-skill (human approval required to install; fallback only).
- Ambiguous requirements -> requirements.

## Checklist (grounded: OO U1-U2, Usabilidade U1/U3)
1. State object/class/attribute/method boundaries; prefer composition over inheritance.
2. Pick exactly one UML diagram type and justify (sequence=time, collaboration=context, execution=physical).
3. UP gate: conception (scope) vs elaboration (architecture baseline + risk elimination).
4. UX: fidelity ladder low->mid->high; apply POUR + Nielsen heuristics + contrast/keyboard checks.
5. Output: diagram prompt + class sketch + UX acceptance for the brief.
